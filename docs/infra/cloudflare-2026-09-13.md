# Cloudflare — DriveDash infrastructure handoff

DriveDash runs entirely on the Cloudflare free plan: one Worker (built with OpenNext), one KV namespace, one custom domain on a zone already managed by Cloudflare. No paid features, no R2, no D1, no Durable Objects, no cron triggers.

## Configuration — `wrangler.jsonc`

```jsonc
{
  "name": "drivedash",
  "main": ".open-next/worker.js",
  "compatibility_date": "2026-09-11",
  "compatibility_flags": ["nodejs_compat"],
  "routes": [{ "pattern": "drivedash.shubhammathur.in", "custom_domain": true }],
  "vars": { "MAX_USERS": "30" },
  "assets": { "directory": ".open-next/assets", "binding": "ASSETS" },
  "kv_namespaces": [
    { "binding": "ACCESS", "id": "41268e2d0a9640ffa18029e8b209966a", "preview_id": "322695c514cf4f31825d78d540828853" }
  ]
}
```

- `custom_domain: true` makes Cloudflare create the DNS record and certificate automatically on deploy; nothing to configure in the DNS tab.
- `open-next.config.ts` is the default `defineCloudflareConfig()` (no incremental cache / R2).
- `next.config.ts` calls `initOpenNextCloudflareForDev()`, which is why `next dev` sees `.dev.vars` and KV bindings locally (miniflare).
- Type shims: `cloudflare-env.d.ts` (generated by `wrangler types`, do not hand-edit) and `kv-namespace.d.ts` (hand-written minimal `KVNamespace`, `Fetcher`, `CloudflareEnv`).

## Secrets and variables

| Name | Kind | Purpose |
|---|---|---|
| `AUTH_SECRET` | secret | Auth.js JWT/cookie encryption. Rotating it signs everyone out |
| `AUTH_GOOGLE_ID` | secret | OAuth client id (public value, stored as secret for convenience) |
| `AUTH_GOOGLE_SECRET` | secret | OAuth client secret |
| `AUTH_URL` | secret | `https://drivedash.shubhammathur.in` — must match the redirect URI registered in Google |
| `AUTH_TRUST_HOST` | secret | `true` |
| `ADMIN_EMAILS` | secret | comma list; currently `mathurshubham@gmail.com`. Admins bypass the seat cap and see `/admin/users` |
| `MAX_USERS` | var (in `wrangler.jsonc`) | seat cap, default 30, clamped 1..100 in code |
| `ALLOWED_EMAILS` | **deleted** 2026-09-13 | legacy allowlist seed; no code reads it |

Local mirrors: `.env.local` (Next dev, `AUTH_URL=http://localhost:3000`) and `.dev.vars` (wrangler, same content). Both gitignored; `.env.example` documents the keys.

## KV namespace `ACCESS`

Created with `wrangler kv namespace create ACCESS` (+ `--preview`). Keys written by `src/lib/access.ts`:

| Key | Content |
|---|---|
| `users` | `{ version: 1, users: [{ email, name?, firstSeenAt, lastSeenAt, blocked? }] }` — the user registry; admins are not stored |
| `allowlist`, `allowlist:seeded`, `requests` | **legacy** from the short-lived approval flow (PR #2). `allowlist` is read once to migrate into `users` if `users` is missing; otherwise ignored. Safe to delete from the dashboard once `users` exists |

Reads are cached 60 s per isolate. Writes go through `guardedPut` in `src/lib/kv-budget.ts`: optional writes (`lastSeenAt` refresh, max once per user per 24 h) are skipped past 200/day per isolate; essential writes (registration, block, remove, account deletion) throw past 500/day → HTTP 503 `kv_budget_exceeded`. Free tier limits are 100k reads and 1k writes per day; expected load is a handful of writes per week.

Inspect from the CLI: `wrangler kv key get --namespace-id 41268e2d0a9640ffa18029e8b209966a users`. Or Dashboard → Storage & Databases → KV → ACCESS.

## Deploy

```
fnm use 22            # or: fnm exec --using=22.23.2 -- <command>
pnpm install
pnpm build && pnpm typecheck && pnpm lint && pnpm test
pnpm run deploy       # opennextjs-cloudflare build && opennextjs-cloudflare deploy
```

Deploy prints the version id and the bound resources (`env.ACCESS` KV, `env.ASSETS`, `env.MAX_USERS`). Typical build+upload ≈ 60 s. The Worker bundle is ~10 MB uncompressed / 2.4 MB gzipped, within free-plan limits.

Production smoke after every deploy:

```
B=https://drivedash.shubhammathur.in
curl -sI $B/ | head -1                      # 307 → /about
curl -s -o /dev/null -w '%{http_code}\n' $B/about $B/login $B/privacy $B/terms   # 200s
curl -s -o /dev/null -w '%{http_code}\n' "$B/api/search?q=x"                     # 401
curl -s $B/api/auth/providers                # google provider with the right callbackUrl
```

Local preview of the real Worker: `cp .env.local .dev.vars` (adjust `AUTH_URL` to the preview port), `pnpm run preview` or `wrangler dev --port 8799` (port 8787 is often taken on this machine).

## Rollback

Dashboard → Workers & Pages → `drivedash` → Deployments → pick a previous version → Rollback. Or `wrangler rollback`. Secrets and KV are unaffected by rollbacks. Every deploy in this project is also a merge commit on `main`, so `git revert` + redeploy is the code-level path.

## Logs and observability

- `wrangler tail` streams live logs (Node 22).
- Dashboard → Workers → `drivedash` → Metrics shows requests, errors, CPU time. Free plan: 100k requests/day, 10 ms CPU per request (I/O waiting does not count).
- Console errors from the app are only client-side; there is no server-side error sink. Consider Workers Logs (free tier available) if debugging in production becomes necessary.

## Costs and limits to remember

- Workers free: 100k requests/day, 10 ms CPU/request. Drive calls are I/O, so CPU stays low.
- KV free: 100k reads, 1k writes, 1k deletes, 1k list per day, 1 GB.
- Custom domain and certificate: free on the zone.
- If the app ever exceeds the free request quota it returns errors rather than billing; the plan has no overage charges.

## Things not to do

- Do not rename the Worker (impossible; you would create a new one — that is how `doc-sharing-tool` became `drivedash`). If you must, re-push all secrets, update `AUTH_URL`, add the new redirect URI in Google, then delete the old Worker.
- Do not put `MAX_USERS` or `ADMIN_EMAILS` into code; they are read lazily from env on each request so a `wrangler secret put` takes effect without a deploy (vars in `wrangler.jsonc` need a deploy).
- Do not run `pnpm deploy` (pnpm's own command). Use `pnpm run deploy`.
- Do not add a cron trigger without revisiting the "no stored refresh token" decision in `docs/claude_memory/doc-sharing-tool-phase2.md`.
