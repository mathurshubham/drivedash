## Audience (publishing status)

- **User type:** External (personal Gmail owner, so Internal was not available).
- **Publishing status:** **In production**, published 2026-09-13. Unverified.
- Consequences of "published, unverified" with a restricted scope:
  - Every new user sees "Google hasn't verified this app" once → Advanced → Go to DriveDash (unsafe) → consent. Existing consents are remembered.
  - **100-user lifetime cap** counted by Google across the project's life; cannot be reset. New consents are blocked past it. The app's own `MAX_USERS=30` is well inside.
  - Refresh tokens do not expire on a schedule (they did every 7 days in Testing mode).
  - Google may email about verification; for a personal-use app under 100 users this is not required (see "When verification is not needed" in Google's docs). Verification would need brand verification, a demo video, and an annual CASA security assessment (~$540/year at the cheapest lab) because `drive` is a **restricted** scope. Decision: not pursuing.
- **Back to testing** exists on the Audience page and is reversible, but reverting re-imposes the 7-day token expiry and the test-user list (test users currently listed: `mathurshubham@gmail.com`).

## Data access (scopes requested by the app)

| Scope | Class | Why |
|---|---|---|
| `openid`, `email`, `profile` | non-sensitive | identity, greeting name, allowlist/registry key |
| `https://www.googleapis.com/auth/drive` | **restricted** | search, metadata, download/export, create permissions (share), copy files, create `Client Shares/` folders, revoke permissions the app created |
| `https://www.googleapis.com/auth/drive.appdata` | non-sensitive | `hotlist.json` and `shares.json` in the hidden appDataFolder |

Scopes are declared in `src/lib/auth.ts` (`SCOPES`) with `access_type=offline` and `prompt=consent`. Changing scopes forces re-consent for every user and, if a new sensitive/restricted scope is added, re-triggers the unverified screen.

`drive.file` would remove the cap and the warning screen but only sees files opened through the Google Picker; search across Drive would be impossible. Not chosen.

## Where user data lives on Google's side

- Each user's **appDataFolder** (hidden, per-app, per-user): `hotlist.json` (shelves) and `shares.json` (share ledger). Only DriveDash can read them; the user can wipe them via Google Account → Security → Third-party apps → DriveDash → Remove access, or in-app via Menu → Delete my data (which also revokes the token).
- `Client Shares/<Client>/` folders and copies in the user's **My Drive** — regular files, visible to the user, never deleted by the app.
- Permissions the app created on the user's files (anyone-with-link or specific emails, optionally with `expirationTime`). Revoked by the sweep, by the Share log, or by Delete my data.

Nothing is stored in Google Cloud itself: no Cloud Storage, no Firestore, no service accounts.

## Common operations

- **Add a redirect URI** (new domain): Clients → `doc-sharing-tool web` → Authorised redirect URIs → Add → Save. Also add the domain under Branding → Authorised domains (the console usually adds it automatically). Then set the Cloudflare secret `AUTH_URL`.
- **Rotate the client secret**: Clients → client → Add secret → copy once → update `AUTH_GOOGLE_SECRET` in `.env.local`, `.dev.vars`, and `wrangler secret put AUTH_GOOGLE_SECRET` → disable the old secret after deploy.
- **See how many users consented**: Audience page → OAuth user cap meter.
- **Revoke the app's access for one account** (test the "not authorised" path): https://myaccount.google.com/permissions with that account.
- **Check Drive API usage**: APIs & Services → Google Drive API → Metrics.

## Things not to do

- Do not upload a logo or submit for verification unless you intend to complete CASA.
- Do not switch to Internal (not available for a Gmail-owned project) or to a Workspace-owned project without re-creating the client and re-pointing the app; all users would have to re-consent and appDataFolder contents would be per-client-project (they would appear empty under a new project).
- Do not add scopes casually; each addition re-prompts every user.
